1.4 Clear-before-set และ macro ใน stm32f4xx.h

/* PA5 → output, push-pull, low speed, ON */
RCC->AHB1ENR  |= RCC_AHB1ENR_GPIOAEN;      // clock ก่อนเสมอ
GPIOA->MODER  &= ~GPIO_MODER_MODER5;       // ล้าง 2 บิต (11:10)
GPIOA->MODER  |= (0b01 << GPIO_MODER_MODER5_Pos);
GPIOA->OTYPER &= ~GPIO_OTYPER_OT5;         // push-pull
GPIOA->OSPEEDR&= ~GPIO_OSPEEDR_OSPEED5;    // low speed
GPIOA->ODR    |= GPIO_ODR_OD5;             // HIGH

GPIO_MODER_MODER5 คือ mask ของทั้งฟิลด์ = 0b11 << 10 ส่วน GPIO_MODER_MODER5_Pos = 10 คือตำแหน่งบิต

กับดักจาก Appendix 1ถ้า MODER เดิมเป็น 0xFFFFFFFF แล้วสั่ง |= (0b01 << 6) จะได้ PA3 = 11 (analog) เหมือนเดิม เพราะ OR ทำให้บิตเป็น 0 ไม่ได้ ต้อง &= ~(0b11 << 6) ก่อน
กับดักGPIOA->MODER |= GPIO_MODER_MODER5; ตั้งทั้งสองบิตเป็น 1 → PA5 กลายเป็น analog ไม่ใช่ output

1.7 ODR กับ BSRR

GPIOA->ODR |= … เป็น read-modify-write (อ่าน → แก้ → เขียน 3 จังหวะ) ถ้า interrupt มาแก้ ODR ระหว่างนั้น ค่าอาจถูกเขียนทับ ส่วน GPIOA->BSRR = (1U << 5) (set PA5) และ GPIOA->BSRR = (1U << 21) (reset PA5) เป็นการเขียนครั้งเดียวที่ไม่กระทบขาอื่น Toggle ใช้ GPIOA->ODR ^= GPIO_ODR_OD5

1.8 Polling, blocking function และ for-loop delay

t = DELAY_THRESHOLD × 12 / 16,000,000  →  1 รอบ = 750 ns  →  1 s ≈ 1,333,333 รอบ

สไลด์หน้า 34 พิมพ์ตัวหารเป็น 1,600,000 ซึ่งพิมพ์ผิด ผลลัพธ์ 750 ns ที่ถูกมาจากการหารด้วย 16,000,000

  • Polling: CPU วนเช็คสถานะเอง (เหมือนเดินไปดูว่าคนส่งอาหารมาหรือยังเป็นระยะ) ส่วน Interrupt คือให้ event มาเรียก CPU เอง
  • Blocking function: ไปบรรทัดถัดไปไม่ได้จนกว่าเงื่อนไขจะเป็นจริง เช่น for-loop delay และการรอ TXE หรือ RXNE
  • อันตรายของ blocking: พลาด deadline หรือ event, watchdog reset, และกินไฟเพราะ CPU ไม่ได้ sleep
  • Lab 1.5: LED PA5 toggle แล้ว delay 1 s → กระพริบ 0.5 Hz (คาบ 2 s) และปุ่ม PB4 ตอบช้าได้ถึง ≈1 s
  • HAL_Delay(ms) ก็เป็น blocking: วนรอจน HAL_GetTick() (นับโดย SysTick interrupt ทุก 1 ms) เพิ่มครบ ความถี่กระพริบ = 1 / (2 × delay) เช่น toggle + HAL_Delay(250) = 2 Hz

UART

Universal Asynchronous Receiver Transmitter: serial (ส่งทีละบิต) แบบ asynchronous (ไม่มี clock ร่วม) ใช้ 2 สาย Tx และ Rx บน Nucleo USART2 ต่อกับ ST-Link ที่ PA2 (TX) และ PA3 (RX) และแปลงเป็น USB Virtual COM port

2.1 พื้นฐานการสื่อสาร

  • Parallel: ส่งหลายบิตพร้อมกันหลายสาย เร็วแต่ใช้สายมาก Serial: ส่งทีละบิต ใช้สายน้อยกว่า ส่งระยะไกลได้ดีกว่า
  • Synchronous: มีสาย clock ร่วม receiver รู้จุด sample จาก clock Asynchronous: ไม่มี clock ทั้งสองฝั่งต้องตกลง baud rate เดียวกัน
  • Bit time = 1 / baud เช่น 9600 → 104.17 µs, 115200 → 8.68 µs
  • Oversampling: receiver สุ่มเร็วกว่า baud 16× (หรือ 8× เมื่อ OVER8 = 1) แล้วใช้ majority vote ตรงกลางบิต เพื่อทนสัญญาณรบกวนและการคลาดของ clock

2.2 Frame format

  • Idle = 1
  • Start bit = 0 (falling edge ใช้ sync)
  • Data 8 หรือ 9 บิต (บิต M) ส่ง LSB first
  • Parity (ไม่บังคับ): even หรือ odd
  • Stop = 1 ยาว 1, 0.5, 2 หรือ 1.5 บิต (CR2 STOP = 00, 01, 10, 11) ถ้าตำแหน่ง stop ไม่ใช่ 1 จะเกิด framing error
STM32เมื่อเปิด parity (PCE = 1) บิตบนสุดของ word จะกลายเป็น parity เช่น M = 0 กับ PCE = 1 ได้ data 7 บิต + parity 1 บิต

ตัวอย่างจากสไลด์: ส่ง 'A' (0x41) แบบ 8 data, odd parity, 1 stop, 9600 bps

0x41 = 0100 0001 → ส่ง LSB ก่อน: 1 0 0 0 0 0 1 0 · มีบิต 1 อยู่ 2 ตัว odd parity จึงเติม 1 · รวม 11 บิต × 104.17 µs = 1.146 ms ต่อ frame

3.4 Clock, sampling time และเวลาแปลง

T_conv = (Sampling cycles + Resolution cycles) / ADCCLK , ADCCLK = PCLK2 / {2,4,6,8} (ADC->CCR ADCPRE)
  • ใช้ HSI 16 MHz และ ADCPRE = /2 จะได้ ADCCLK = 8 MHz (ADCCLK สูงสุด 36 MHz)
  • Sampling time ต่อช่อง (SMPR2 สำหรับช่อง 0–9, SMPR1 สำหรับช่อง 10–18) เลือกได้ 3 / 15 / 28 / 56 / 84 / 112 / 144 / 480 cycles
  • ตัวอย่าง: 84 + 12 = 96 cycles ÷ 8 MHz = 12 µs หรือ 3 + 12 = 15 cycles = 1.875 µs
  • ช่วง sampling คือช่วงที่ตัวเก็บประจุ sample-and-hold ชาร์จจากแหล่งสัญญาณ ถ้าแหล่งมี impedance สูงต้องเพิ่ม sampling time ไม่เช่นนั้นค่าจะต่ำกว่าจริงและแกว่ง

3.6 Trigger: software vs hardware

  • SWSTART ใน main loop: จังหวะขึ้นกับโค้ด jitter สูง
  • SWSTART ใน timer ISR: ดีขึ้น แต่ยังแกว่งตาม interrupt latency, ISR อื่นที่ priority สูงกว่า และช่วงที่ปิด interrupt
  • Timer TRGO → ADC: TIMx_CR2 MMS = 010 (update → TRGO) และ ADC EXTSEL = TIMx_TRGO, EXTEN = 01 เริ่มแปลงตรงจังหวะฮาร์ดแวร์ jitter ต่ำสุด
  • Continuous: เร็วสุด แต่อัตราขึ้นกับ ADCCLK และ sampling time ไม่ได้ล็อกกับเวลาที่ต้องการ

3.7 การเก็บผล: polling · interrupt · DMA

  • Interrupt: เปิด EOCIE ใน CR1 แล้วใน ADC_IRQHandler อ่าน DR (การอ่านล้าง EOC)
  • DMA: ADC1 ใช้ DMA2 Stream0 (หรือ Stream4) Channel 0 ตั้ง CR2.DMA = 1 และ DDS = 1 ร่วมกับ DMA circular mode
  • Half-Transfer / Transfer-Complete: ใช้ buffer แบบ ping-pong ประมวลผลครึ่งที่เต็มขณะ DMA เติมอีกครึ่ง ต้องทำให้เสร็จก่อน DMA วนกลับมา เช่น 128 ค่าที่ 8 kHz มีเวลา 16 ms
  • Overrun (OVR): ค่าใหม่มาก่อนอ่านค่าเก่า (เมื่อ DMA = 1 หรือ EOCS = 1) ข้อมูลหายและ DMA หยุด ต้องล้าง OVR แล้วเริ่มใหม่

Interrupt

Interrupt คือสัญญาณที่หยุด flow ปกติชั่วคราวเพื่อให้ CPU ตอบ event สำคัญทันที เหมือนคนส่งอาหารโทรมาเรียก แทนที่เราจะเดินไปดูเป็นระยะ (polling)

4.1 เกิดอะไรขึ้นเมื่อ interrupt มา

  1. Peripheral ตั้ง flag (เช่น EXTI PR, USART RXNE) และถ้าเปิด interrupt enable ของ peripheral ไว้ ก็จะส่ง request ไป NVIC
  2. NVIC ตรวจว่าเปิด IRQ นั้นไว้หรือไม่ และ priority สูงกว่างานปัจจุบันหรือไม่
  3. CPU push R0–R3, R12, LR, PC, xPSR ลง stack อัตโนมัติ แล้วอ่าน address ของ ISR จาก vector table (latency ≈12 cycles)
  4. ISR ทำงาน และต้องล้าง flag ของ peripheral
  5. Return: ถ้ามี IRQ อื่นค้างจะ tail-chain ต่อทันที ถ้าไม่มีก็คืนค่าจาก stack แล้วกลับไปทำงานเดิม
3 ด่านที่ต้องผ่าน(1) enable ที่ peripheral เช่น EXTI_IMR, RXNEIE, EOCIE, UIE (2) NVIC_EnableIRQ(x_IRQn) (3) interrupt รวมไม่ถูกปิด (PRIMASK, __enable_irq()) ขาดด่านใดด่านหนึ่ง ISR ไม่ทำงาน

4.2 Priority และ preemption

  • F411 ใช้ priority 4 บิต (0–15) เลขน้อย = สำคัญกว่า ตั้งด้วย NVIC_SetPriority(IRQn, p)
  • ISR ที่ priority สูงกว่าขัด (preempt) ISR ที่ต่ำกว่าได้ (nesting)
  • ISR ที่ priority เท่ากันหรือต่ำกว่าต้องรอ (pending) จนกว่าตัวที่กำลังทำงานจะจบ
  • ถ้าค้างพร้อมกันหลายตัว ตัวที่ priority สูงสุดได้ก่อน ถ้าเท่ากัน IRQ number น้อยกว่าได้ก่อน
  • ISR ยาวจะเพิ่ม latency ของทุกตัวที่ priority ต่ำกว่าหรือเท่ากัน

4.3 EXTI สำหรับปุ่ม

  • EXTI line 0–15 รับจากขาเลขเดียวกันของพอร์ตใดพอร์ตหนึ่ง เลือกพอร์ตใน SYSCFG_EXTICR (ต้องเปิด SYSCFGEN ใน APB2ENR) หนึ่ง line เลือกได้แค่หนึ่งพอร์ต PB13 กับ PC13 จึงใช้ EXTI พร้อมกันไม่ได้
  • EXTICR[n/4] ฟิลด์ที่ (n mod 4) กว้าง 4 บิต รหัสพอร์ต A = 0000, B = 0001, C = 0010, D = 0011, E = 0100, H = 0111
  • EXTI registers: IMR (unmask), RTSR (rising), FTSR (falling), SWIER (software trigger), PR (pending, ล้างโดยเขียน 1)
  • Vector: EXTI0, EXTI1, EXTI2, EXTI3, EXTI4 แยกกัน · EXTI9_5 ใช้ร่วม line 5–9 · EXTI15_10 ใช้ร่วม line 10–15 (ใน ISR ร่วมต้องเช็ค PR ว่าเป็น line ไหน)
  • ปุ่ม pull-up (active-low) กดแล้วเปลี่ยนจาก 1 เป็น 0 จึงใช้ falling edge

4.4 กฎการเขียน ISR

  • สั้น: ล้าง flag, เก็บค่า, ตั้ง flag แล้วออก งานหนัก (sprintf, ส่ง UART, คำนวณ) ไปทำใน main หรือ DMA
  • ห้าม block: ไม่ใช้ for-loop delay และไม่วนรอ TXE ใน ISR
  • volatile ทุกตัวแปรที่ ISR กับ main ใช้ร่วมกัน ไม่เช่นนั้น optimizer อาจอ่านค่าแค่ครั้งเดียว
  • ล้าง flag ให้ถูกวิธี: EXTI PR เขียน 1, USART RXNE อ่าน DR, ADC EOC อ่าน DR, TIM UIF เขียน 0 ถ้าไม่ล้าง ISR จะวนซ้ำ
  • Critical section: การ read-modify-write ตัวแปรร่วมใน main ให้ครอบด้วย __disable_irq() / __enable_irq() สั้นๆ

4.5 Debounce และ handler ของ peripheral อื่น

ปุ่มกลไกเด้ง 5–20 ms ทำให้เกิดหลาย edge วิธีที่ดีคือเก็บ timestamp จาก timer ใน ISR แล้วทิ้ง edge ที่ห่างจากครั้งก่อนน้อยกว่า ~30 ms หรือปิด IMR ชั่วคราวแล้วให้ timer เปิดคืน ห้ามใช้ delay ใน ISR

void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin){
  if (GPIO_Pin == GPIO_PIN_13){          // callback ใช้ร่วมทุก line

  }
